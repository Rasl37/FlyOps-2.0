Экспериментальная биоморфная распределенная архитектура, реализующая симуляцию среза нервной системы дрозофилы (*Drosophila melanogaster*) из 19 взаимосвязанных нейронов внутри кластера Kubernetes.

Проект демонстрирует концепции высокой доступности (High Availability) распределенных систем, устойчивости микросервисного меша, динамического обнаружения сервисов (Service Discovery через CoreDNS), предотвращения штормов запросов (Storm Prevention), двухуровневого самовосстановления (L4 self-healing ReplicaSet + L7 перемаршрутизация при сбое сокетов) и сквозной визуализации топологии в реальном времени через Prometheus Operator и Grafana Node Graph.

## Архитектурный обзор

FlyOps 2.0 проецирует биологические нейронные цепи на децентрализованный микросервисный граф, где каждый нейрон представляет собой автономную сетевую единицу в изолированном контейнере. В архитектуре отсутствует единая точка отказа (SPOF) и центральный брокер сообщений: передача потенциала действия выполняется через асинхронные P2P HTTP/TCP вызовы с динамическим разрешением через DNS-фабрику Kubernetes.

### Ключевые инженерные решения

1. **Децентрализованный Service Discovery**: Узлы взаимодействуют напрямую по внутренним FQDN именам CoreDNS (`http://neuron-XX.flyops.svc.cluster.local:8080/stimulate`). Центральный оркестратор маршрутизации в рантайме не задействован.
2. **Защита от штормов через рефрактерный период (400 мс)**: В биологии нейрон физически не способен повторно генерировать спайк в фазе деполяризации. В FlyOps реализован жесткий рефрактерный барьер 400 мс на каждом поде. Все импульсы, приходящие в течение этого интервала, отбрасываются с HTTP-кодом `429 Too Many Requests / Dropped`. Это предотвращает циклический саморазогрев сети и паралич процессора (CPU Starvation).
3. **Двухуровневый механизм отказоустойчивости (Self-Healing)**:
   - **Уровень 4 (Инфраструктурный / Оркестратор)**: Контроллер Kubernetes `ReplicaSet` непрерывно сверяет состояние кластера. При падении контейнера из-за нехватки памяти (OOMKilled) или системного сбоя под немедленно пересоздается, возвращаясь в строй за считанные секунды.
   - **Уровень 7 (Прикладной / Сервисный меш)**: Если исходящее TCP-соединение не получает ответа дольше 50 мс или возвращает ошибку 5xx, микросервис-отправитель активирует динамический fallback-роутинг, мгновенно перенаправляя импульс по резервной синаптической ветви без потери целостности сквозного сигнала.
4. **Сквозная наблюдаемость (Observability)**: Сбор кастомных OpenMetrics через Prometheus Operator и формирование направленного взвешенного графа в панели Grafana Node Graph с отображением задержек на ребрах и частоты срабатываний.

## Механизмы отказоустойчивости

### 1. Подавление широковещательного шторма (Anti-Cascade)
В сложных нейронных сетях с рекуррентными петлями положительная обратная связь неизбежно провоцирует лавинообразное лавирование трафика (broadcast storm).

FlyOps 2.0 предотвращает каскадный коллапс с помощью атомарной проверки временной метки внутри асинхронного цикла обработки:

$$\Delta t = t_{\text{current}} - t_{\text{last\_depolarization}}$$

$$\text{Действие} = \begin{cases} \text{Провести импульс дальше}, & \text{если } \Delta t \ge 400\text{ мс} \\ \text{Инкремент счетчика отброшенных и Abort}, & \text{если } \Delta t < 400\text{ мс} \end{cases}$$

Эта математическая граница гарантирует детерминированное потребление системных ресурсов даже при жесткой аномальной внешней нагрузке на входной сенсорный слой.

### 2. Динамический L7-фейловер синапсов
Каждый микросервис хранит собственную таблицу смежности синаптических путей. Если основной downstream-узел не отвечает в пределах установленного окна задержки, клиент активирует резервное плечо:

```python
async def forward_pulse(primary_target: str, fallback_target: str, payload: dict):
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(primary_target, json=payload, timeout=0.050) as resp:
                if resp.status == 200:
                    METRICS_FORWARDED.labels(status="success", route="primary").inc()
                    return await resp.json()
    except (asyncio.TimeoutError, aiohttp.ClientError):
        METRICS_FAILOVER.inc()
        # Переключение на резервный синаптический маршрут
        async with aiohttp.ClientSession() as session:
            async with session.post(fallback_target, json=payload, timeout=0.050) as resp:
                METRICS_FORWARDED.labels(status="success", route="fallback").inc()
                return await resp.json()
```

### 3. Автоматическое восстановление уровня L4 (Kubernetes)
Каждый под обеспечен конфигурацией `livenessProbe` и `readinessProbe` по эндпоинту `/healthz`. При утечке памяти, блокировке цикла событий (deadlock) или фатальном сбое рантайма kubelet принудительно убивает дефектный контейнер и запускает чистый инстанс.

## Инструкция по развертыванию

### Требования к окружению
- ОС: Linux (рекомендуется Ubuntu 22.04 LTS или Debian 12)
- [Minikube](https://minikube.sigs.k8s.io/docs/start/) (версии 1.30.0+) или готовый кластер Kubernetes v1.28+
- Установленный и настроенный CLI `kubectl`
- Менеджер пакетов `helm` v3+

### Шаг 1: Инициализация кластера Minikube
Запустите локальный кластер, выделив ресурсы под работу 19 микросервисов и стека мониторинга:

```bash
minikube start \
  --cpus=4 \
  --memory=8192 \
  --disk-size=25g \
  --driver=docker \
  --kubernetes-version=v1.28.3
```

Проверьте готовность ноды:
```bash
kubectl get nodes
```

### Шаг 2: Установка Prometheus Operator
Разверните стек мониторинга Prometheus Operator для поддержки кастомного ресурса `ServiceMonitor` и веб-интерфейса Grafana:

```bash
helm repo add prometheus-community [https://prometheus-community.github.io/helm-charts](https://prometheus-community.github.io/helm-charts)
helm repo update

helm install monitoring-stack prometheus-community
